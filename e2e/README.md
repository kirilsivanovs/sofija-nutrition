# 🎭 E2E Testing с Playwright

## Что это?

Playwright E2E тесты защищают критические бизнес-процессы от некачественного кода. Эти тесты запускаются в реальном браузере и проверяют работу всего приложения целиком (Frontend + Backend + Database).

## Почему Playwright, а не Selenium?

| Критерий | Playwright ✅ | Selenium |
|----------|--------------|----------|
| Скорость | Быстрее в 2-3 раза | Медленнее |
| Надежность | Auto-wait, retry | Нужно вручную ждать |
| API | Современный, async/await | Устаревший |
| Debugging | Отличный (UI mode) | Сложный |
| Скриншоты/видео | Автоматически | Настраивать вручную |
| Multi-browser | Да (Chrome, Firefox, Safari) | Да |
| TypeScript | Из коробки | Нужна настройка |
| Maintenance | Microsoft активно развивает | Старая библиотека |

## Какие критические процессы покрыты?

### 🚨 Критический процесс #1: Просмотр услуг
- Клиент видит список услуг
- Клиент может выбрать услугу
- Клиент видит календарь
- Клиент может выбрать дату

**Если падает** → Клиенты НЕ МОГУТ БРОНИРОВАТЬ

### 🚨 Критический процесс #2: Загрузка слотов
- После выбора даты загружаются слоты
- Клиент может выбрать время
- Показывается сообщение если нет слотов

**Если падает** → Клиенты НЕ МОГУТ ВЫБРАТЬ ВРЕМЯ

### 🚨 Критический процесс #3: Создание бронирования
- Форма имеет все обязательные поля
- Клиент может создать бронирование
- Валидация работает

**Если падает** → БРОНИРОВАНИЯ НЕ СОЗДАЮТСЯ

### 🚨 Критический процесс #4: API работает
- Health check возвращает OK
- API возвращает список услуг
- API возвращает слоты для даты

**Если падает** → BACKEND НЕ РАБОТАЕТ

### 🚨 Критический процесс #5: Мультиязычность
- Латышский язык работает
- Английский язык работает
- Русский язык работает

**Если падает** → Часть клиентов не видят контент

## Как запускать тесты?

### Запуск всех E2E тестов (headless)
```powershell
npm run test:e2e
```

### Запуск с визуальным интерфейсом (рекомендуется для дебага)
```powershell
npm run test:e2e:ui
```

### Запуск с видимым браузером
```powershell
npm run test:e2e:headed
```

### Дебаг режим (пошаговое выполнение)
```powershell
npm run test:e2e:debug
```

### Посмотреть отчет после запуска
```powershell
npm run test:e2e:report
```

### Запуск конкретного теста
```powershell
npx playwright test critical-business-flows.spec.js
```

### Запуск конкретного describe блока
```powershell
npx playwright test -g "Просмотр услуг"
```

## Что проверяют тесты?

Playwright тесты проверяют:
- ✅ UI элементы отображаются
- ✅ Кнопки кликабельны
- ✅ Формы заполняются
- ✅ API запросы работают
- ✅ Навигация работает
- ✅ Валидация срабатывает
- ✅ Ошибки обрабатываются
- ✅ Мультиязычность работает

## Когда запускать E2E тесты?

### ✅ Локально при разработке

Запускайте в UI mode для быстрого тестирования:
```powershell

```

## Структура теста

```javascript
test('Описание что проверяем', async ({ page }) => {
  // 1. Открыть страницу
  await page.goto('/');
  
  // 2. Найти элемент
  const button = page.locator('button');
  
  // 3. Выполнить действие
  await button.click();
  
  // 4. Проверить результат
  await expect(page.locator('.success')).toBeVisible();
});
```

## Добавление новых E2E тестов

### Когда добавлять?

- ✅ Новая критичная функциональность
- ✅ Баг который вернулся несколько раз
- ✅ Сложный user flow
- ✅ Интеграция с внешним сервисом

### Как добавлять?

1. Создать новый файл в `e2e/`:
```powershell
New-Item e2e/payment-flow.spec.js
```

2. Написать тест:
```javascript
import { test, expect } from '@playwright/test';

test.describe('Оплата консультации', () => {
  test('Клиент может оплатить консультацию', async ({ page }) => {
    // Ваш тест
  });
});
```

3. Запустить:
```powershell
npm run test:e2e
```

## Best Practices

### ✅ DO:
- Используйте `data-testid` для стабильных селекторов
- Проверяйте критичные user flows
- Делайте тесты независимыми друг от друга
- Используйте осмысленные названия тестов
- Группируйте тесты по функциональности

### ❌ DON'T:
- Не тестируйте стили (цвета, шрифты)
- Не делайте тесты зависимыми от других тестов
- Не используйте хрупкие селекторы (по тексту на русском)
- Не тестируйте то, что уже покрыто unit тестами
- Не делайте очень длинные тесты (>20 шагов)

## FAQ

**Q: Нужно ли запускать API и Frontend вручную перед тестами?**
A: Нет, Playwright автоматически запустит через `webServer` в конфиге.

**Q: Можно ли запускать E2E тесты без интернета?**
A: Да, все работает локально.

**Q: Как часто нужно запускать E2E тесты?**
A: Обязательно перед каждым merge в main. Локально - по необходимости.

**Q: Что делать если тест нестабильный (flaky)?**
A: 1) Добавить явные ожидания, 2) Проверить селекторы, 3) Увеличить timeout.

**Q: Сколько времени занимает запуск всех E2E тестов?**
A: ~1-2 минуты в headless режиме.

## Troubleshooting

### Проблема: Тесты не находят элементы
**Решение:** Используйте `data-testid` атрибуты вместо классов/текста

### Проблема: Тесты падают с timeout
**Решение:** Увеличьте timeout в конфиге или используйте явные ожидания

### Проблема: Browser не запускается
**Решение:** Переустановите браузеры: `npx playwright install`

### Проблема: API не отвечает
**Решение:** Проверьте что API запущен на порту 7071
