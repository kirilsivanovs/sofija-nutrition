# Что умеет система? (Возможности Sofija Nutrition)

## 📋 Общее описание

**Sofija Nutrition** - это полнофункциональная система онлайн-бронирования консультаций нутрициолога. Система автоматизирует процесс записи клиентов, управление расписанием и администрирование услуг.

## 📊 База данных (5 таблиц)

### 1. `bookings` - Бронирования
**Что хранит:**
- ID клиента и детали контактов
- Выбранная услуга и дата/время
- Статус бронирования
- Цена на момент бронирования
- Онлайн или очная консультация

**Операции:**
- Создание новых бронирований
- Обновление статусов
- Поиск по дате и клиенту
- Проверка пересечений

### 2. `adminSettings` - Настройки администратора
**Что хранит:**
- Рабочие часы для каждого дня недели
- Список отпусков и каникул
- Заблокированные даты
- Конфигурация расписания

**Операции:**
- Обновление рабочих часов
- Добавление/удаление отпусков
- Блокировка/разблокировка дат

### 3. `Services` - Услуги
**Что хранит:**
- Названия услуг на всех языках
- Цены и валюта
- Продолжительность консультаций
- Доступные форматы (онлайн/очно)

**Операции:**
- Создание новых услуг
- Обновление цен и описаний
- Кэширование (5 минут)

### 4. `FeatureFlags` - Флаги функций
**Что хранит:**
- Названия функций
- Статус (включено/выключено)
- Описание функции

**Операции:**
- Включение/выключение функций
- Проверка доступности функций
- Кэширование (2 минуты)

### 5. `ServicesHistory` - История изменений
**Что хранит:**
- Все изменения услуг с меткой времени
- Старые и новые значения
- Версия изменения

**Операции:**
- Автоматическое сохранение при изменениях
- Аудит изменений цен
- Восстановление предыдущих версий

## 🚀 API Endpoints

### Публичные API (доступны всем)

#### 1. Получение доступных слотов
```
GET /api/availability?serviceId={id}&date={YYYY-MM-DD}
```
**Что возвращает:**
- Список доступных временных слотов для выбранной услуги и даты
- Учитывает рабочее время, отпуска и существующие бронирования

#### 2. Создание бронирования
```
POST /api/bookings
```
**Что делает:**
- Проверяет доступность выбранного времени
- Валидирует все входящие данные
- Создает бронирование в базе данных
- Отправляет email-подтверждение клиенту

#### 3. Подтверждение оплаты
```
POST /api/payments/confirm
```
**Что делает:**
- Обновляет статус бронирования на "подтверждено"
- Отправляет финальное подтверждение

#### 4. Получение списка услуг
```
GET /api/services
```
**Что возвращает:**
- Все активные услуги с ценами и описаниями
- Данные кэшируются на 5 минут

### Административные API (требуют авторизации)

#### 5. Управление бронированиями
```
GET /api/admin/bookings
PUT /api/admin/bookings/{id}
DELETE /api/admin/bookings/{id}
```

#### 6. Управление расписанием
```
GET /api/admin/settings
PUT /api/admin/settings
```

#### 7. Управление услугами
```
GET /api/admin/services
POST /api/admin/services
PUT /api/admin/services/{id}
GET /api/admin/services/{id}/history
```

#### 8. Управление feature flags
```
GET /api/admin/features
PUT /api/admin/features/{name}
```

## ✨ Уникальные возможности

### 1. Умное управление слотами (Mutable Slots)
Система не хранит фиксированный список слотов, а **динамически рассчитывает** доступные времена на основе:
- Рабочих часов
- Существующих бронирований
- Отпусков и блокировок
- Продолжительности выбранной услуги

**Преимущество:** Изменение расписания мгновенно отражается на доступности.

### 2. Версионирование услуг
При каждом изменении цены или параметров услуги:
- Старая версия сохраняется в таблицу `ServicesHistory`
- Существующие бронирования сохраняют цену на момент создания
- Можно отследить историю всех изменений

**Преимущество:** Прозрачность ценообразования и защита от споров.

### 3. Feature Flags без деплоя
Софья может включать/выключать функции через админ-панель:
- Новую услугу можно добавить, но не показывать клиентам
- Тестировать функции перед публикацией
- Быстро отключить проблемную функцию

**Преимущество:** Гибкость без технических знаний и перезапуска.

### 4. Многоуровневое кэширование
- **Services**: 5 минут (редко меняются, часто запрашиваются)
- **Feature Flags**: 2 минуты (могут меняться чаще)
- **Availability**: динамический расчет (всегда актуально)

**Преимущество:** Баланс между производительностью и актуальностью данных.

### 5. Защита от гонок (Race Conditions)
При попытке забронировать один и тот же слот двумя клиентами одновременно:
- Система проверяет доступность в момент создания
- Использует транзакции Azure Table Storage
- Только одно бронирование будет создано

**Преимущество:** Нет двойных бронирований.
